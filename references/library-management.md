# 论文库编号、日期与台账管理

在登记论文、创建视频工程、完成归档、修正开始日期或迁移目录时读取。本约定用于配套的论文视频工作区；用户当次明确约定优先。新制作流程采用下述候选与完成目录分工，已有未编号或旧位置论文只在当前任务包含相应整理时调整。换声、字幕修复和更新 skill 不触发全库整理。

## 编号、命名与日期

- 业务根目录为 `candidate_paper/`、`paper/` 与 `remotion/`。候选目录保存待制作和制作中的论文 PDF；`paper/` 保存已完成视频生成与验收的论文 PDF 及统一台账；`remotion/` 保存各论文工程与视频。登记工具、迁移映射和备份放在 `remotion/_library/`。
- 论文按登记顺序分配永久编号 `P0001` 起，跨年递增、不回收、不随排序变化。一次读取已有编号后沿用，不根据目录数量重新推算。
- 用户可将原文件名 PDF 直接放入 `candidate_paper/`，无需预先编号。处理指定论文或按用户要求登记时，再完成身份核对与规范命名，不因发现其他候选就自动批量处理。
- 登记后 PDF 使用 `P0001__YYYY-MM-DD__完整英文题名.pdf`，制作期间仍位于 `candidate_paper/`；工程为 `remotion/P0001__YYYY-MM-DD__完整英文题名/`。编号、日期、文件题名一致，工程 basename 等于 PDF 去掉 `.pdf`。原题与原文件名保留在登记记录，文件名仅规范化不允许的字符和多余空白；正确引用含空格路径，名称冲突时先核对论文身份和版本。完成归档只改变 PDF 父目录。
- 日期表示开始阅读或解读日期，默认时区 `Asia/Shanghai`；发表、导入、开始解读、视频完成日期分别记录。后续修订或重新导出不改变开始日期。未开始用 `pending`，开始时换为实际日期，不预建空视频工程。
- 历史开始日期优先采用明确阅读笔记或项目开始记录。需要推定时记录证据并在台账标注“推定”；文件修改时间不能直接充当开始日期。仍无法确定时保留待核实状态，不将已开始论文误标为待读，不强行完成该条改名。
- 周总结放在 `remotion/conclusion/W0001__YYYY-MM-DD_to_YYYY-MM-DD/`，独立分配永久 W 编号，记录实际覆盖的完整日期范围及论文 P 编号，不占用论文编号。

英文音轨与对应中英双语字幕属于同一视频、同一论文工程。新工程的内部结构见 [制作流程](production-workflow.md) 的“多论文目录与清理”；历史多版本或分离子工程按当前范围保留，外层加编号不自动合并内部工程。

## 台账与来源身份

`paper/catalog.json` 是覆盖已登记候选、制作中和已完成论文的统一权威记录，`paper/README.md` 是生成的阅读入口；候选目录不建立第二套台账。沿用现有字段与生成工具，避免手工维护两份互相冲突的记录。登记应能关联永久编号、原题及 DOI（如有）、指定 PDF 版本与 SHA-256、开始日期及依据、工程、英文主笔记、播放入口、实际输出及验收记录，并分别记录成片数量、配音语言和字幕语言集合。`pdf` 字段保存实际相对路径，可以指向 `candidate_paper/` 或 `paper/`；未产生的交付物不填成已交付链接。

同时查找两个论文目录和台账，按编号、原题、DOI、PDF 哈希查重。相同 PDF 沿用已有编号和工程，已有成片时先定位实际交付物，再按本次请求决定是否需要修改；不把重复投递当成另一篇新论文。同一 DOI 对应不同 PDF 时核对版本，不静默覆盖；同名但不同论文不能混用工程。用户提供的旧路径失效时，先查台账和新旧路径映射定位文件。

来源记录应关联登记编号、开始日期、实际 PDF 相对路径及哈希；主笔记链接到对应来源。相对路径以脚本实际解析基准计算，不因语言子目录或历史嵌套工程改变层级而失效。路径迁移只修改引用，不改写旁白中的原题。

“已交付”依据当前要求范围内的实际文件、来源身份、匹配的验收记录及哈希。默认范围是一个英式英语配音、中英双语字幕的视频及其双语 SRT 等交付物，不以存在中文配音版作为完成条件。历史多版本项目分别保留实际状态；若工具仍将双版通过作为唯一完成条件，应按当前交付范围适配状态判断，中文配音明确记为未要求，不伪造其通过记录或为通过检查额外制作。技术验收不能代替完整人工听审或论文实验复现。

## 日常操作

先读取工作区的 `AGENTS.md`、台账和管理说明，并检查现有工具是否支持候选目录、制作期间保留 PDF、完成后归档及相关路径校验。部分旧版 `library.py` 的 `register`、`start` 会固定将 PDF 放入 `paper/`，不能直接套用。实际制作任务中，对当前流程所需的工具能力做最小适配并验证后再执行，不借此迁移全库；单独更新 skill 时只记录兼容要求，不自动改造工作区工具。

已具备兼容的 `remotion/_library/library.py` 时沿用其接口；以下是登记、开始与同步接口的示例，占位值须替换为当前论文的信息，从工作区根目录执行，不代表旧实现已经兼容：

```sh
python3 remotion/_library/library.py register --pdf 'candidate_paper/original-paper.pdf' --title 'Full English title' --doi '10.example/identifier'
python3 remotion/_library/library.py start PNNNN --date YYYY-MM-DD
python3 remotion/_library/library.py sync
python3 remotion/_library/library.py check
```

`--doi` 可省略。流程如下：

1. **登记。** 跨两个目录和台账确认身份后登记 PDF，使用返回的永久编号，在 `candidate_paper/` 内规范命名；待读论文保持 `pending`。
2. **开始。** 任务实际开始时记录日期，候选 PDF 改用实际开始日期并保留在候选目录，再创建相同 basename 的工程。已有开始日期时沿用；确需修正，使用兼容工具的 `start PNNNN --date YYYY-MM-DD --correct`，由工具同步 PDF、已有工程及相关引用，不分别手工改名。
3. **制作。** 默认制作单个英式英语配音、中英双语字幕的视频；读取并复用已有合格内容。首次制作期间 PDF 留在候选目录；只完成阅读、讲稿、配音、预览或部分渲染，以及任务中断或验收未通过，都不触发归档。
4. **验收与归档。** 当前要求的成片和交付物生成并通过验收后，按下述“完成归档”将 PDF 移入 `paper/`，核对内容哈希和有效引用。归档操作使用工作区实际具备并验证过的能力，不假定存在某个固定命令。
5. **同步。** 制作、交付或修改后运行兼容工具的 `sync` 和 `check`，核对实际路径、来源身份、语言及交付状态；完成归档后再次核对来源路径和链接。工具不能识别历史结构时显式关联其文件与验收记录，不能靠改成 PASS 掩盖问题。

这些命令属于工作区工具，skill 不附带该脚本。若不存在，先检查工作区是否有等价工具；全新工作区按上述约定建立最小登记记录与 Markdown 入口，后续需要时在工作区实现相应能力。已有未编号库按本次授权范围处理，不能因工具缺失借机全库迁移。历史一次性迁移脚本不是初始化或日常登记命令，不从旧项目盲目复制运行。

## 完成归档

首次制作完成的依据是当前要求范围内的实际成片、交付物与匹配的验收记录，不能仅凭某个 MP4 或输出目录存在就归档。验证通过后，把源 PDF 从 `candidate_paper/` 移到 `paper/`，保留永久编号、文件名、开始日期和 PDF 字节内容；核对目标哈希与登记哈希一致。工程保持原位置，完成日期不替换文件名中的开始日期。

移动前检查目标冲突并记录旧 → 新路径。目标已存在且哈希相同时，沿用已核对的文件和登记记录；重复来源仅在身份与有效引用核对后按当前范围处理。目标哈希不同则先解决论文身份或版本冲突，不能覆盖。已完成论文的后续修订继续沿用 `paper/`、原编号和工程，不移回候选目录，也不因重新导出再次归档。

归档同步更新台账的实际 PDF 路径、生成的阅读入口、工程来源记录、英文主笔记及有效脚本或链接引用，保持来源身份校验可用。历史验收记录保留原事实和范围，通过路径映射或补充归档检查记录衔接，不批量改写为新的通过结果。归档未完成时如实记录实际位置，不能只改台账路径宣告完成。

本次归档仅检查实际受影响的 PDF、引用和来源身份；若渲染输入未变，无需重合成配音或重渲染视频。更广泛的目录变更按下述迁移流程执行；更新技能本身不自动把既有待读论文移回候选目录或整理其他历史文件。

## 迁移、验收与回滚

以下步骤用于获授权的目录迁移；修正已有工程开始日期时也适用于实际移动的部分。

1. **保存迁移依据。** 确认源路径、目标路径和冲突，记录旧 → 新映射、当前登记状态、拟修改文本及环境入口备份；记录 PDF、成片、字幕、封面、音轨和其他保留素材的哈希。默认不建立旧名符号链接，当前入口改由台账提供。
2. **移动并修复。** 保留内容和版本，更新来源记录、脚本、主笔记、播放器、台账与跨论文引用。检查 Python 虚拟环境中的绝对路径、Node 可执行链接、浏览器和素材缓存；必要时重建环境入口并核对依赖版本，避免无关升级。
3. **验证实际可用性。** 核对保留文件哈希、来源身份、链接和环境命令；运行受影响工程的必要检查，并对实际受影响的视频渲染短片、检查原成片播放及章节跳转。历史多版本播放器要确认所操作视频的实际源路径，不能只检查第一个 video 元素或元数据。纯迁移不重合成旁白、不重新导出完整视频。
4. **保存新验收与恢复依据。** 原有验收保留其时间、范围与事实，新迁移检查单独存放。回滚应在任何覆盖前核对保留文件和迁移后的文本状态，发现后续修改时拒绝覆盖；回滚后重新迁移需要重新核对当前状态，不能直接重放过期计划。

验收通过后再处理本次范围内明确不需要的过程文件，清理边界见 [制作流程](production-workflow.md) 的“多论文目录与清理”。清理后修正对已删除试听、归档和旧工程的有效依赖；将已缺失的历史版本如实标为未重新检查，不能把另一版本当作其替代证据。

交付目录整理结果时提供台账入口、新旧路径映射及实际检查范围。不要将某次迁移的文件数量、短片秒数或 PASS 记录写成未来任务的固定验收门槛。
